## 1. Objective

Establish the foundational directory structure and Pydantic schema layer for the AsyncFlow Engine — a multi-step LLM workflow orchestration service built on FastAPI, Redis Queue (RQ), and Ollama (Llama 3.1).

**Strict constraint enforced:** No LLM logic was written. The entire focus of this phase was data validation correctness and project scaffolding.

## 3. Tasks Carried Out

### 3.1 Package Initialisation
Created `__init__.py` files for all four Python packages: `app`, `app.api`, `app.core`, `app.worker`. Each contains a module-level docstring for discoverability.

### 3.2 FastAPI Application (`app/main.py`)
- Instantiated `FastAPI` with title, description, version metadata.
- Implemented async `lifespan` context manager (replaces deprecated `on_event` handlers) for startup/shutdown hooks — Redis pool initialisation will go here.
- Registered `workflow_router` under `/workflow` prefix.
- Added `CORSMiddleware` (permissive for development, tighten in production).
- Added a `/health` liveness probe endpoint.

### 3.3 Environment Configuration (`app/core/config.py`)
- Used `pydantic-settings` `BaseSettings` to load all config from environment variables and `.env` file.
- Wrapped in `@lru_cache(maxsize=1)` singleton — avoids redundant env parsing on every request.
- Covered: `REDIS_URL`, `RQ_QUEUE_NAME`, `JOB_TIMEOUT`, `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_REQUEST_TIMEOUT`, `APP_ENV`, `LOG_LEVEL`.

### 3.4 Pydantic Schemas (`app/core/schemas.py`) — **Primary Deliverable**

#### Enumerations
| Enum | Members |
|---|---|
| `TaskType` | `summarize`, `translate`, `extract_json`, `classify`, `sentiment`, `custom_prompt` |
| `WorkflowStatus` | `queued`, `running`, `completed`, `failed`, `cancelled` |
| `StepStatus` | `pending`, `running`, `completed`, `failed`, `skipped` |

#### Step Configurations (Discriminated Union via `task_type`)
| Model | Key Fields |
|---|---|
| `SummarizeConfig` | `max_words` (10–2000), `style` |
| `TranslateConfig` | `target_language` (BCP-47), `preserve_formatting` |
| `ExtractJsonConfig` | `output_schema` (JSON Schema dict), `strict` |
| `ClassifyConfig` | `labels` (min 2), `multi_label` |
| `SentimentConfig` | `granularity` (document/sentence) |
| `CustomPromptConfig` | `prompt_template`, `temperature` (0–2), `max_tokens` |

#### Core Request/Response Models
- `WorkflowStep` — wraps a `StepConfig` with `step_id`, `input_override`, `retry_on_failure`.
- `WorkflowSubmitRequest` — root payload: validates `step_ids_must_be_unique` (field validator) and `validate_translate_not_first` (model validator).
- `WorkflowSubmitResponse` — returns `task_id` + acceptance message.
- `StepResult` — per-step output with timing data and computed `duration_seconds` property.
- `WorkflowStatusResponse` — full poll response with `step_results[]` and `final_output`.

### 3.5 API Routes (`app/api/routes.py`)
- `POST /workflow/submit` → returns `202 ACCEPTED` + `task_id`.
- `GET /workflow/{task_id}/status` → returns `404` stub until Redis persistence is wired.
- Both endpoints are fully typed with request/response models.

### 3.6 Worker Stubs
- `engine.py` — `LLMEngine` class with typed `generate()` stub and documented error types.
- `queue_tasks.py` — `process_workflow(request_dict: dict)` function stub. Accepts `dict` (not Pydantic model) intentionally — justified in docstring due to RQ pickle serialisation safety.

### 3.7 Infrastructure Files
- **`docker-compose.yml`** — Redis 7 Alpine with AOF persistence, health check, and optional RedisInsight UI behind a `--profile debug` flag.
- **`requirements.txt`** — Grouped: FastAPI/Uvicorn, Pydantic, RQ/Redis, httpx, pytest.
- **`.env`** — Template only. All values are safe defaults, no secrets.
- **`.gitignore`** — Covers Python cache, venvs, IDE files, `.env`, Docker volumes, logs.
- **`README.md`** — Full architecture diagram, quick-start steps, task type table, example JSON payload, development status table.

## 4. Design Decisions & Rationale

| Decision | Rationale |
|---|---|
| Discriminated union for `StepConfig` | Pydantic resolves the correct model via `task_type` literal — zero ambiguity, full type safety, easily extensible |
| `lru_cache` singleton for Settings | Avoids repeated env parsing; settings are immutable post-startup |
| `202 ACCEPTED` for submit endpoint | Workflow is async — returning 200 would imply completion |
| Dict-based RQ serialisation | Pickle safety across process boundaries; Pydantic models are reconstructed inside the worker |
| `validate_translate_not_first` model validator | Guardrail against a common misuse pattern; can be relaxed via config later |
| Redis AOF persistence in Docker | Prevents job loss on container restart during development |
