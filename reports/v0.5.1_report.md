## 2. Architecture Changes

### 2.1 — New Route: `GET /dlq` (Top-Level)

The v0.5.0 `/dlq` endpoint was mounted under the `/workflow` router prefix, making the
fully-qualified URL `GET /workflow/dlq`. The user directive specified `GET /dlq` (root-level).

In v0.5.1, a dedicated `get_dlq_top_level()` handler is registered directly on the `app` instance
in `main.py` (not via the `workflow_router`), yielding the canonical URL:

```
GET http://localhost:8000/dlq
```

The `/workflow/dlq` route is **retained** for backward compatibility.

**Route table (v0.5.1):**

| Method | Path | Handler | Tag |
|---|---|---|---|
| `POST` | `/workflow/submit` | `submit_workflow` | Workflow |
| `GET` | `/workflow/{task_id}/status` | `get_workflow_status` | Workflow |
| `GET` | `/workflow/dlq` | `get_dlq_entries` | Dead-Letter Queue |
| `GET` | `/dlq` | `get_dlq_top_level` | Dead-Letter Queue |
| `GET` | `/health` | `health_check` | Meta |

### 2.2 — Pagination via `limit` Query Parameter

Both DLQ endpoints now accept an optional `limit` query parameter:

```
GET /dlq?limit=50
GET /workflow/dlq?limit=100
```

- Type: `int`, range: `1-1000`
- Default: `DLQ_MAX_ENTRIES` setting (default `500`)
- Implemented via `LRANGE dlq_key 0 (limit-1)` — O(limit), not O(N)

**Configuration:**

```python
# app/core/config.py
DLQ_MAX_ENTRIES: int = 500  # Override via env: DLQ_MAX_ENTRIES=100
```

### 2.3 — `_on_job_retried` Callback Wiring

**Root cause (v0.5.0):** `_on_job_retried()` was defined in `run_worker.py` but never attached to
the `SimpleWorker` instance. Result: no `[RETRYING]` log lines were emitted at the RQ layer.

**Fix (v0.5.1):** Monkeypatch `worker.handle_job_failure` after worker instantiation.

```python
_original_handle_failure = worker.handle_job_failure

def _patched_handle_failure(job, queue, started_job_registry=None, exc_string=""):
    retries_left = getattr(job, "retries_left", 0)
    if retries_left and retries_left > 0:
        _on_job_retried(job, queue)
    return _original_handle_failure(
        job, queue,
        started_job_registry=started_job_registry,
        exc_string=exc_string,
    )

worker.handle_job_failure = _patched_handle_failure
```

**Resilience:** The monkeypatch is wrapped in a `try/AttributeError` block. DLQ routing is
completely unaffected since it is wired at enqueue time via `on_failure=route_to_dlq`.

## 7. Known Limitations (Carried Forward from v0.5.0)

| Item | Notes |
|---|---|
| No DLQ replay endpoint | `GET /dlq` is read-only. `POST /dlq/replay` planned for v0.6. |
| DLQ list grows unbounded | `DLQ_MAX_ENTRIES` mitigates API response size but does not prune the Redis list. Production should implement periodic `LTRIM`. |
| `attempt` count is approximate | `total_attempts = RQ_RETRY_MAX + 1` is static; actual count requires job metadata introspection. |
| `handle_job_failure` monkeypatch | Works with RQ 1.15-2.x. `AttributeError` guard ensures silent degradation on future RQ major versions. |
